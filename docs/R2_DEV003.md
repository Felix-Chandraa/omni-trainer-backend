# R2 DEV-003 — Existing F1 live-bus subscriber (diagnostic)

**Scope:** Read-only subscribe to existing PyQt/Feather F1 WebSocket server at `127.0.0.1:8765`. No simulator launcher changes, no UDP listener on existing `5503`, no MAVLink command, no process kill, no install/sudo. Uses Python 3 stdlib only.

**Why this path:** Existing `src/main_window.py::update_hud` publishes UI-normalized payload using `self.bus.publish_telemetry(payload)` in `src/telemetry_bus.py`. It includes `pose_source`, position, and reported autopilot statuses. This is already a derived stream, *not* raw FGNetFDM packets or MAVLink messages. A `pose_source=fg` value is evidence of frontend-reported FG ownership, not independent raw validation. Startup of the existing application and transport success still need testing on the user's current checkout.

**Steps:** Start existing simulator in another terminal using your working recipe. Leave it running. In a second terminal:

```bash
cd ~/Downloads
bash install_omni_r2_dev003.sh --live --seconds 15
```

If initial install has not run, execute without `--live` first. Specify `--base /home/felix/omni-r2-dev001-hyAZEv` when auto-discovery selects another folder. Script does not launch `run_demo.sh` because the supplied snapshot has fixed ports and broad cleanup.

**Output:** separate diagnostic Session/Attempt in `runtime/dev003/dev003-*.sqlite`, with Attempt remaining `Setup`; `bus-*.jsonl` sampled at up to 10 Hz. `gap_start`/`gap_end` events on >2s silence. Files are diagnostic and not assessment evidence. State rows use source `existing_f1_ui_bus`, `synthetic=false`. No claims of synchronized truth/AV or real control authority. Retain results if you need to compare reconnects.

**Classification:** BUS UNAVAILABLE = listener not accessible; CONNECTED/NO TELEMETRY = no valid data received; UI TELEMETRY RECEIVED = stream exists without FG pose flag; LIVE UI BUS + FG POSE FLAG = derived telemetry shows FG ownership. Direct raw dual-channel proof requires explicit non-conflicting stream mirrors in a later integration; never attach a second UDP receiver to `5503`.
