# OMNI R2 DEV-004 — Attempt-scoped Aircraft Worker lifecycle

Status: engineering foundation only; **not** R2 acceptance, flight validation, or training release.

## What DEV-004 adds

- `AttemptWorkerCoordinator` binds an owned subprocess to an existing Session/Exercise/Attempt.
- Only the assigned instructor Actor may start/health/stop that worker in this slice.
- Duplicate worker start is rejected.
- The same `aircraft_id` cannot be leased concurrently to a second Attempt in one coordinator.
- Runtime metadata is written atomically to `worker.json` under an Attempt/generation-specific directory.
- Worker start/exit/stop/reap events are appended to the existing R2 metadata store.
- Unexpected child exit becomes `healthy=false`; it is never reported as healthy just because an Attempt still exists.
- Stop uses only the owned process group created by the existing `AircraftWorker`; no `pkill`, `killall`, or project-wide process search.

## Deliberately NOT implemented yet

- No production `run_demo.sh` execution from the worker. Legacy cleanup behavior must not be inherited blindly.
- No ArduPilot/JSBSim launcher adapter or per-worker port plan yet.
- No raw MAVLink/FGNetFDM demultiplexing inside the worker.
- No authoritative full pause/resume or continuity recovery.
- No process adoption after coordinator restart. Persistent `worker.json` is diagnostic metadata, not proof we can safely take ownership of an old PID.
- No production login/auth, capability release checks, or remote API.

## DEV-004 demo

The demo launches only `python -c 'sleep'` as an owned child, checks health, writes a manifest, and stops it. It never starts or stops the OMNI simulator.

## Next engineering slice

DEV-005 should reconcile the actual OMNI launch chain (`run_demo.sh`, ArduPilot SITL, standalone JSBSim dependency/workaround, visual stack) and introduce a **trusted launcher adapter** with explicit runtime directories and port allocation. Before controlling production processes, it should first support a dry-run/inspect mode and preserve the existing known-good launcher path for regression.
