# R2 DEV-005 — OMNI Launcher Adapter / Reconciliation

DEV-005 menutup celah antara lifecycle worker DEV-004 dan launcher OMNI existing.
Tahap ini **belum menyalakan simulator dari worker**. Tujuannya membuat kontrak launch
headless yang eksplisit dan dapat diaudit sebelum side effect production diizinkan.

## Yang dibuat

- `omni_launcher_adapter.py`: menemukan source OMNI, memvalidasi file runtime, memilih
  executable JSBSim secara deterministik, mengaudit `run_demo.sh`, dan membangun plan.
- `omni_managed_entry.py`: wrapper `exec` tanpa PyQt yang kelak berjalan di dalam
  process-group milik AircraftWorker. Tidak memakai `pkill`, tidak wipe EEPROM, dan
  tidak menyalin model saat startup.
- `omni_launcher_cli.py`: preflight read-only pada checkout aktual + dry-run argv.

## Keputusan dari audit snapshot

`run_demo.sh` existing tetap berguna sebagai reference path untuk demo 1+1, tetapi
belum aman dijadikan child worker langsung karena cleanup-nya dapat menutup seluruh
proses yang berasal dari checkout ArduPilot yang sama. Ia juga menyinkronkan model ke
pohon ArduPilot saat startup. R2 memisahkan instalasi/configuration dari lifecycle.

Repo juga mempunyai `omnitrainer-sitl/omni_launcher`, tetapi launcher itu berbasis
PyQt/QProcess. DEV-005 mengambil kontrak `sim_vehicle.py`/profile yang relevan tanpa
membawa GUI sebagai dependency backend.

## Batas DEV-005

- Belum ada managed launch ArduPilot/JSBSim nyata.
- Mission loader existing ditunda karena masih memiliki fallback endpoint SITL tetap;
  DEV-006 harus mengikat companion process ke alokasi port/runtime worker.
- Port internal multi-instance belum diklaim terverifikasi.
- Model hash mismatch hanya dilaporkan; DEV-005 tidak memperbaikinya diam-diam.
- Full pause, command application, raw channel ownership, dan restart recovery tetap
  pekerjaan R2 berikutnya.
