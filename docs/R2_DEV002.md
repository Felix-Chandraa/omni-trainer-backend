# OMNI R2 DEV-002 — Read-only telemetry engineering slice

Status: prototype. DEV-001 untouched; no acceptance of G3, no actual SITL run asserted.

## Installed
- `fg_adapter.py`: strict 408-byte FGNetFDM v24 decoder, local UDP receiver, backlog drain, read-only. Physical pose always sourced from FG; `agl_raw_m` is raw, not verified datum/terrain clearance.
- `mav_observer.py`: optional pymavlink read-only state observer; HEARTBEAT, GLOBAL_POSITION_INT, GPS_RAW_INT, SYS_STATUS. No send, stream request, mission download or MAVLink ACK routing.
- `state_journal.py`: append-only diagnostic JSONL per run containing attempt/aircraft identity, source, sequence, monotonic/UTC receive timestamps, synthetic flag. It is **not** validated flight truth, synchronized media or assessment evidence.
- `observer_cli.py`: offline synthetic Session/Exercise/Attempt and two example samples. `--live` attaches only to explicitly configured local UDP streams for a bounded duration. Does not start or own simulator.
- `tests/test_r2_dev002.py`: offline decoder/UDP/provenance/decoder tests.

## Run

From the folder printed by installer:

```bash
python3 -m unittest discover -s tests -v
python3 -m src.training_core.observer_cli
```

Optional live observation only **after** arranging a dedicated copy of MAVLink and FG streams to the selected ports, without disrupting the running UI:

```bash
# Activate the Python venv that already has pymavlink first.
python3 -m src.training_core.observer_cli --live --fg-port 15504 --mav-port 15555 --seconds 10
```

Default ports 15504/15555 are intentionally different from existing production ports. Without an explicit copy of both streams, expected output is `NO DATA`, not PASS. Do not bind FG 5503 when existing PyQt frontend is using it, and do not automatically kill any process. A sender configured only for UDP 5503 cannot be observed from 15504. If your setup does not support duplication, skip live and retain existing renderer. The script performs no reconfiguration of any running process.
