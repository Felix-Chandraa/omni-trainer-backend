# R2 DEV-008 — Authorized Active Start + Readiness Invalidation

## Purpose

DEV-007 connected real worker health and fresh FG/MAV evidence to
`Setup -> Ready`.

DEV-008 closes the next R2 state contract:

`Ready -> Active`

The transition is allowed only through a trusted backend start gate that
revalidates:

- Attempt is currently Ready;
- Attempt ID / aircraft ID / generation still match;
- the exact worker PID that supplied evidence is still owned and running;
- FG evidence is valid and fresh;
- MAVLink HEARTBEAT evidence is valid and fresh;
- the evidence bundle itself is fresh;
- SessionManager still authorizes the assigned instructor and revision.

The gate does not start another worker and emits no flight command. Therefore
entering Active is state/audit authorization only in this slice.

## Readiness invalidation

R2 requires Ready to be invalidatable. DEV-008 adds an explicit trusted path:

`Ready -> Setup`

for monitor-detected failures such as worker loss, device/configuration change,
or other readiness loss. A client-provided boolean is not sufficient; the
trusted monitor supplies failure codes plus a reason.

DEV-008 intentionally does not automatically invalidate Ready merely because a
Start request was rejected. Background monitoring/invalidation and the start
request remain separate responsibilities.

## Limits

This is not yet R4 authority/HOTAS or full pause/resume. It does not claim:
- flight command routing is enabled on Active;
- HOTAS ownership is validated;
- payload readiness;
- full pause physics hold;
- mission loading;
- scoring/assessment.

## Live acceptance

- actual managed OMNI worker starts;
- trusted evidence creates Ready;
- a fresh second evidence bundle revalidates before Active;
- Ready -> Active keeps the same worker PID/generation;
- no automatic worker restart occurs;
- short Active continuity remains healthy;
- events are persisted;
- scoped cleanup releases SITL ports.
